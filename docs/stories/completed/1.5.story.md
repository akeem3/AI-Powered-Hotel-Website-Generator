# Story 1.5: Booking Flow & Rooms Page Implementation

> **Epic:** Epic 1 - Core Hotel Website Infrastructure
> **Status:** Done
> **Priority:** High
> **Story Points:** 8
> **Version:** 1.0
> **Created:** 2025-10-22

## 1. The "Why" (Rationale)
This story provides the complete booking foundation that enables:

- User conversion through streamlined booking process
- Comprehensive room comparison and selection in dedicated space
- Data collection for availability checking with mock validation
- Responsive design patterns for mobile/desktop booking flow
- Component validation patterns for LLM reference implementation
- Complete user journey from homepage to room selection

## 2. The "What" (Description)
**As a** potential guest interested in booking a room at The Sterling Executive hotel,
**I want** to use a booking widget to select dates and preferences, and view available rooms in an organized layout,
**So that** I can easily check availability, compare room options, and proceed with the booking process efficiently.

### AC7: ZOD Contract Implementation for Booking System

- [x] Create ZOD schema for BookingWidget component:
  ```typescript
  export const BookingWidgetContract = z.object({
    variant: z.enum(["mobile", "desktop"]).default("desktop"),
    onSubmit: z.function().optional(),
    className: z.string().optional(),
    defaultValues: z
      .object({
        checkIn: z.date().optional(),
        checkOut: z.date().optional(),
        adults: z.number().min(1).max(10).default(2),
        children: z.number().min(0).max(5).default(0),
        rooms: z.number().min(1).max(5).default(1),
      })
      .optional(),
  });
  ```
- [x] Create ZOD schema for BookingData validation:
  ```typescript
  export const BookingDataContract = z
    .object({
      checkIn: z.date(),
      checkOut: z.date(),
      adults: z.number().min(1).max(10),
      children: z.number().min(0).max(5),
      rooms: z.number().min(1).max(5),
      roomType: z.string().optional(),
      specialRequests: z.string().max(500).optional(),
    })
    .refine((data) => data.checkOut > data.checkIn, {
      message: "Check-out date must be after check-in date",
    });
  ```
- [x] Add runtime validation to booking form submission
- [x] Implement contract validation error handling with user-friendly messages
- [x] Test booking validation with edge cases (invalid dates, occupancy limits)
