# Story 2.2: Define CVA Variants + ZOD Schemas for All Components

> **Epic:** Epic 2 - Foundation Validation & Prompt Development
> **Status:** ✅ Complete
> **Priority:** Critical
> **Story Points:** 10
> **Version:** 1.0

## 1. The "Why" (Rationale)
Establishes type-safe variant system (CVA) and runtime validation (ZOD) for all 8 components, **ensuring CVA variants use Story 1.11 design system tokens** to enable per-hotel theming without refactoring:

- **Type Safety:** CVA provides compile-time variant validation
- **Runtime Validation:** ZOD schemas catch invalid LLM outputs
- **Design System Integration:** CVA uses semantic tokens for per-hotel theming
- **Epic 7 Foundation:** Validated patterns ready for LangGraph automation
- **Progressive Enforcement:** WARNING mode for learning, STRICT mode for production

**CRITICAL:** This story is the validation gateway. If CVA bypasses Story 1.11 tokens, Epic 7 StylingAgent will require complete refactoring. We validate the actual production architecture now to prevent costly late-stage rework.

## 2. The "What" (Description)
**As a** LLM generation system,
**I want** type-safe component variants with runtime validation integrated with the centralized design system,
**So that** generated components have consistent styling, predictable props, and use semantic design tokens.
