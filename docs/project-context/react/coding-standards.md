## Storybook Workflow

### Development Cycle

When creating or modifying components:

1. **Develop in Isolation**
   - Start Storybook: `npm run storybook`
   - Create/update component story
   - Test all variants visually

2. **Document Variants**
   - Create story for each CVA variant
   - Add Storybook controls for props
   - Include responsive variants (Mobile, Desktop)

3. **Visual Regression**
   - Push changes to branch
   - Chromatic captures snapshots
   - Review visual changes in Chromatic UI

### Story File Template

```typescript
// stories/2-Components/[ComponentName]/[ComponentName].stories.tsx

import type { Meta, StoryObj } from '@storybook/react';
import ComponentName from '@/components/blocks/ComponentName';

const meta: Meta<typeof ComponentName> = {
  title: 'Components/Blocks/ComponentName',

  parameters: {

      description: {

      },
    },
  },

  },
};

export default meta;
type Story = StoryObj<typeof ComponentName>;

export const Default: Story = {
  args: {
    // Default props
  },
};
```

## Core Principles

### 1. KISS (Keep It Simple)
- Write the simplest code that works
- Avoid premature abstraction
- Prefer explicit over clever

### 2. Server Components First
- Default to React Server Components
- Add `'use client'` only when needed
- Minimize client-side JavaScript

### 3. Type Safety
- TypeScript strict mode always
- No `any` types
- Explicit return types

## Component Patterns

### Server Component (Default)
```typescript
// No 'use client' = Server Component
// Can be async, can fetch data directly

export default async function UserPage({
  params,
}: {
  params: { userId: string };
}) {
  const user = await fetchUser(params.userId);

  if (!user) {
    notFound();
  }

  return <UserProfile user={user} />;
}
```

### Client Component (When Needed)
```typescript
'use client';

import { useState, useCallback } from 'react';

interface CounterProps {
  initialValue?: number;
}

export function Counter({ initialValue = 0 }: CounterProps) {
  const [count, setCount] = useState(initialValue);

  const increment = useCallback(() => {
    setCount((prev) => prev + 1);
  }, []);

  return (
    <button onClick={increment}>
      Count: {count}
    </button>
  );
}
```

### When to Use `'use client'`
- **MUST**: useState, useEffect, useRef, other hooks
- **MUST**: Event handlers (onClick, onChange)
- **MUST**: Browser APIs (localStorage, window)
- **MUST NOT**: Data fetching (use Server Components)
- **MUST NOT**: Just for prop drilling

## TypeScript Rules

### Component Props
```typescript
// GOOD - Interface for props
interface UserCardProps {
  user: User;
  onEdit?: (userId: string) => void;
  className?: string;
}

export function UserCard({ user, onEdit, className }: UserCardProps) {
  return /* ... */;
}

// BAD - Inline types, React.FC
const UserCard: React.FC<{ user: User }> = ({ user }) => {
  return /* ... */;
};
```

### Return Types
```typescript
// GOOD - Explicit return type
function formatCurrency(amount: number): string {
  return new Intl.NumberFormat('en-US', {
    style: 'currency',
    currency: 'USD',
  }).format(amount);
}

// BAD - Implicit return type
function formatCurrency(amount: number) {
  return /* ... */;
}
```

### No `any` Types
```typescript
// GOOD - Use unknown with type guard
function processData(data: unknown): ProcessedData {
  if (!isValidData(data)) {
    throw new Error('Invalid data');
  }
  return transform(data);
}

// BAD - any type
function processData(data: any): ProcessedData {
  return transform(data);
}
```

## Hooks Patterns

### Custom Hook Structure
```typescript
/**
 * Hook for managing user authentication state.
 *
 * @returns Authentication state and actions
 *
 * @example
 * const { user, isLoading, login, logout } = useAuth();
 */
export function useAuth() {
  const [user, setUser] = useState<User | null>(null);
  const [isLoading, setIsLoading] = useState(true);

  const login = useCallback(async (credentials: Credentials) => {
    // Implementation
  }, []);

  const logout = useCallback(async () => {
    // Implementation
  }, []);

  return {
    user,
    isLoading,
    isAuthenticated: !!user,
    login,
    logout,
  };
}
```

### Rules of Hooks
- **MUST**: Call at top level only
- **MUST**: Call from React functions only
- **MUST**: Prefix with `use`
- **MUST NOT**: Call conditionally
- **MUST NOT**: Call in loops

## State Management

### Zustand Store
```typescript
import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

interface AuthState {
  user: User | null;
  isLoading: boolean;
  setUser: (user: User | null) => void;
  logout: () => void;
}

export const useAuthStore = create<AuthState>()(
  devtools(
    persist(
      (set) => ({
        user: null,
        isLoading: true,
        setUser: (user) => set({ user, isLoading: false }),
        logout: () => set({ user: null }),
      }),
      { name: 'auth-storage' }
    ),
    { name: 'AuthStore' }
  )
);
```

### React Query
```typescript
export function useUser(userId: string) {
  return useQuery({
    queryKey: ['user', userId],
    queryFn: () => fetchUser(userId),
    staleTime: 5 * 60 * 1000, // 5 minutes
    enabled: Boolean(userId),
  });
}

export function useUpdateUser() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: updateUser,
    onSuccess: (data) => {
      queryClient.invalidateQueries({ queryKey: ['user', data.id] });
    },
  });
}
```

## Anti-Patterns to Avoid

### Never Do This
```typescript
// ❌ any type
const data: any = fetchData();

// ❌ React.FC
const Component: React.FC<Props> = () => {};

// ❌ Index as key
{items.map((item, index) => <Item key={index} />)}

// ❌ Inline object/function in JSX (causes re-renders)
<Component style={{ color: 'red' }} onClick={() => {}} />

// ❌ useEffect for data fetching (use Server Components or React Query)
useEffect(() => {
  fetch('/api/data').then(/* ... */);
}, []);

// ❌ Prop drilling through many levels
<A><B><C><D prop={value} /></C></B></A>
```

### Do This Instead
```typescript
// ✅ Proper typing
const data: UserData = fetchData();

// ✅ Plain function
function Component(props: Props) {}

// ✅ Unique key
{items.map((item) => <Item key={item.id} />)}

// ✅ Memoized values
const style = useMemo(() => ({ color: 'red' }), []);
const handleClick = useCallback(() => {}, []);

// ✅ Server Components or React Query
const data = await fetchData(); // Server Component
const { data } = useQuery({ queryKey: ['data'], queryFn: fetchData });

// ✅ Context or state management
const value = useContext(MyContext);
const value = useMyStore((state) => state.value);
```

## Style Polishing Rules (Story 7.12 AC5.2)

> **Purpose:** Prevent style drift and ensure consistent design system usage at 10,000+ websites scale.

### Core Principles

**❌ NEVER create one-off className fixes**
```typescript
// WRONG - One-off styling
<Button className="w-full px-4 py-2 border-2 border-brand-primary/subtle hover:bg-brand-primary/faint">

// CORRECT - Use CVA variant
<Button className={roomCardButtonVariants({ variant: 'outline' })}>
```

**✅ ALWAYS trace style bug to global pattern**
1. Find the pattern in `/web-app/lib/cva-variants.ts`
2. If pattern doesn't exist, create a new variant
3. Update contract schema to include new variant
4. Document in CVA-ARCHITECTURE.md

**🔄 MUST update CVA variant if pattern is reusable**
```typescript
// If 3+ components use same pattern → Create CVA variant
// If pattern has 2+ states → Create CVA variant
// If pattern may change → Create CVA variant
```

### FORBIDDEN Patterns

| Pattern | Status | Use Instead |
|---------|--------|-------------|
| `bg-red-*`, `text-green-*` | ❌ FORBIDDEN | `bg-status-error`, `text-status-success` |
| `#hex` colors | ❌ FORBIDDEN | `var(--token-name-val)` or semantic utility class like `bg-brand-primary` |
| `style={{}}` objects | ❌ FORBIDDEN | Utility classes or CVA variants |
| Arbitrary values `p-[17px]` | ⚠️ DISCOURAGED | Standard spacing or CVA |
| One-off className strings | ❌ FORBIDDEN | CVA variants |

### Required Process for Style Bug Fixes

1. **Identify the root cause**
   ```bash
   # Search for similar patterns
   grep -r "bg-red-" web-app/components/
   ```

2. **Check if CVA variant exists**
   ```bash
   grep -r "status.*error" web-app/lib/cva-variants.ts
   ```

3. **Fix via CVA or semantic token**
   ```typescript
   // If CVA exists → Use it
   <div className={statusVariants({ type: 'error' })}>

   // If single instance → Use semantic token
   <div className="bg-status-error text-text-primary">
   ```

4. **Run validation script**
   ```bash
   ./scripts/validate-style-patterns.sh
   ```

### Examples: Correct vs Incorrect

| ❌ Incorrect | ✅ Correct |
|-------------|------------|
| `bg-red-50 border-red-200` | `bg-status-error/faint border-status-error/subtle` |
| `text-green-600` | `text-status-success` |
| `style={{ scrollBehavior: 'smooth' }}` | `scroll-smooth-behavior` utility |
| Custom button className | `buttonVariants({ variant: 'outline' })` |
