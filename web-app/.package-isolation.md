# Package Management Isolation

This file ensures that web-app operates as an independent package within the larger platform workspace.

## Why This Structure Works

The `/home/ric/et-llm-websites/` directory is a **platform workspace**, not a Node.js project:

- `web-app/` - Next.js reference implementation (independent package)
- `docs/` - Documentation (no packages)
- `.bmad-core/` - BMAD framework (configuration only)
- `web-bundles/` - Agent bundles (configuration only)

## Package Management Rules

1. **web-app/** is completely self-contained:
   - Has its own package.json
   - Has its own package-lock.json
   - Has its own node_modules/
   - No dependencies on parent directory

2. **Root directory** has no Node.js dependencies:
   - No package.json at root level
   - No lock files at root level
   - Documentation and configuration only

## Build Commands

Always run build commands from within web-app/:

```bash
cd /home/ric/et-llm-websites/web-app
npm install    # Install web-app dependencies only
npm run build  # Build web-app only
npm run dev    # Start development server
npm test       # Run tests
```

## Deployment

The web-app builds to a static site that can be deployed independently:

- Build output: `web-app/out/` (for static export)
- Or `web-app/.next/` (for server deployment)
- Completely independent of platform workspace
